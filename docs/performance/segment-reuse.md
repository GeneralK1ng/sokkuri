# 分词复用（2026-11-17）

## 问题

s2tw、s2twp、s2hk、s2hkp 四档先用 STPhrases 与 Generated 的 union 把全文切段，第一级再用 short_circuit（同一个 union，STCharacters）逐段转换。同一个 union 在每个位置被查两遍：分词一遍，第一级又一遍。s2t 不分词，只查一遍，所以这四档在 JVM 上比 s2t 慢约 1.7 倍。

## 做法

第一级以分词词典开头时，`convert` 把分词与第一级合成一遍扫描（engine 的 `SegmentReuse`）：

- 整词段：分词查到的匹配就是第一级的结果，直接写出它的值。
- 不含 IDS 运算符（U+2FF0–U+2FFF）的未匹配段：union 在段内查不到，只用第一级剩下的词典转换，这四档里就是 STCharacters。
- 含运算符的未匹配段：仍用完整的第一级转换。

“以分词词典开头”指第一级的词典就是分词词典，或者是 short_circuit 组且第一个成员是分词词典。两个词典按结构比较：叶子词典比实例，词典组比策略和成员。配置层从进程级缓存取叶子词典，同一个文件就是同一个实例，所以配置里写法相同的组能被认出来。

其余 12 档不受影响：tw2s、tw2sp、hk2s、hk2sp 的分词用 TSPhrases，第一级却从别的词典开始；其余各档不分词。`inspect` 仍按分词结果逐段转换。

## 为什么输出不变

设分词词典为 S，第一级为 short_circuit（S，R）。

- 整词段 [i, i+L)：L 是 S 在 i 处对整段输入的最长匹配。把文本截到 i+L，只会去掉比 L 长的键，胜出的键不在其中。所以第一级在 i 处匹配同一个键，一步覆盖整段，写出同一个值。
- 不含运算符的未匹配段 [a, b)：段内不可能有 IDS，分词逐个码点走过它。每个位置要么查过 S 而未命中，要么因为码点不是 S 的键首字被跳过。第一级在段内也只停在码点边界上：键都是合法的 UTF-16，b 处又是 S 的键的起点，不会切开代理对。S 截到 b 之后，在这些位置同样查不到，所以第一级每一步的结果都等于 R 的结果。没有 R 时，整段原样写出。
- 含运算符的段：R 的键可能从运算符开始，或者伸进 IDS，第一级随后会停在分词整体吞掉的 IDS 内部，那里 S 没被查过，所以这类段不复用。分词的批量跳过停在每个运算符上，所以段内的运算符要么在分词查过的位置上，要么在从这种位置开始的 IDS 里，扫描时都能发现。

## 验证

- engine：随机生成词典、组合方式与文本（含 IDS 运算符、增补平面字符与不成对的代理），对比合并扫描与逐段转换的输出。同时检查形状判定：结构相同的组必须走合并路径；换了策略、顺序、成员，或换成内容相同的另一个实例，都不能走。另有 IDS 段回退的专项用例。
- 变异检查：植入 10 处错误，全部检出。去掉形状判定的断言后，两处放宽结构比较的变异仍会被输出对比检出。
- runtime：16 档、两种口径下，golden 语料的全部输入与几条 IDS 文本，`convert` 与 `inspect` 的输出一致。
- golden 套件三端通过；`upstream-diff` 两种口径各 303216 次比对，转换与 inspect 都没有差异。

## 代价

- 每个转换器多一个 `SegmentReuse` 对象，以及第一级去掉 S 之后的一个 `Conversion`。STCharacters 的键首字集合按引用共享，不复制。没有单独测量常驻堆。
- 建档时多一次结构比较，只比较引用与策略。冷启动没有单独测量。
