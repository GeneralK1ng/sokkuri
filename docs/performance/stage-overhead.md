# 每级转换的固定开销（2026-10-15）

## 问题

s2tw 的耗时约为 s2t 的两倍，而它多出的那一级词典很小。分段计时表明，主因是 s2tw 多出的 mmseg 分词：s2t 不分词，s2tw、s2twp、s2hk、s2hkp 都先用 STPhrases 与 Generated 的 union 把全文切段，再逐段转换。

s2tw 处理 `long` 样本的耗时构成（单次运行，µs）：

| 环节 | 改动前 | 改动后 |
|---|---|---|
| 归一化（CJK 兼容字） | 5.1 | 2.0 |
| mmseg 分词 | 49.2 | 46.2 |
| 第一级转换（与 s2t 相同） | 66.0 | 61.9 |
| 第二级 TWVariants | 9.9 | 4.6 |
| 其余，主要是 173 段每段每级的复制 | 15.2 | 4.6 |
| 合计 | 145.4 | 119.3 |

另外，JFR 采样显示词典组的 `mayStartKey` 占转换时间的 11%–20%：批量跳过的每个字，都要对组内每个子词典各做一次二分。

## 做法

- 首码点索引查找前先比较上下界，范围外的码点直接返回。CJK 兼容字词典的键都在 U+F900 以上，常用汉字不再二分，归一化由约 5 µs 降到 2 µs。
- 有分词时，转换链一级一级处理全部分段，每级只分配一次缓冲，用偏移记录段边界。此前每段每级都要复制输入并分配多个对象。匹配仍不跨段，输出逐字相同。
- `Dictionary` 新增 `matchLength`：分词只需要边界，不再生成值。
- `Dictionary` 新增键首字集合，词典组合并子词典的集合，`mayStartKey` 由每个子词典各二分一次变为整组一次。后来改为各级在构建时取用不可变的集合，见 [hot-paths.md](hot-paths.md)。

## 代价

当时词典组为每个转换器保留合并后的集合，每个转换器首次转换后多占 15–39 KiB（之前几乎为零）；新进程中的首次转换多出合并集合的时间，s2t 由 2.45 ms 增至 2.98 ms。之后的热点修复把每个转换器的常驻量降到 s2t 10.5 KiB、s2tw 22.1 KiB、t2s 3.5 KiB。

## 验证

- 契约套件的随机对比测试加入了 `matchLength` 与键首字集合；词典组新增嵌套随机组上的一致性测试；转换链新增段隔离测试，以及随机分段下逐级处理与逐段处理一致的测试。每项新测试都经变异检查。
- golden 套件通过；`upstream-diff` 两种口径各 298848 次比对，没有差异。
